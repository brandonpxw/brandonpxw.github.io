Clutch: Uni Deadline Assistant

Previous Next

Personal Project

Clutch is a Telegram bot that keeps track of uni deadlines. You type a deadline the way you'd text a friend, or send a screenshot of an assignment brief, and Clutch saves it, reminds you before it's due and sends a morning summary.

I built it on my own, from the first line of code to running it 24/7 on Google Cloud for free. My friends now use it too, each with their own private list.

The problem

At SIT, deadlines are spread across module pages, slides and emails. I kept finding out about a quiz or a report too late, because nothing put them all in one place and reminded me in time.

I set myself two rules: it had to be as easy as sending a text, and it had to respect school systems and privacy. That meant no scraping the school portal and no forwarding school email.

What I built

  • Adding deadlines in plain words. Messages like "add a lab next weds 8pm and a math quiz" become two deadlines. Gemini reads the message and returns structured fields, and screenshots of assignment briefs work the same way.
  • Asking instead of guessing. If a date, time, name or module is missing, Clutch asks with buttons rather than making something up.
  • Answers in plain words. "How many CS2102 tests do I have left?" is answered from your own list.
  • Made for Singapore universities. A profile matches short forms like "ict se" to 179 official programmes across SIT, NUS, NTU, SMU, SUTD and SUSS, each with its own term system. Deadlines are then tagged to your modules automatically.
  • Reminders and a morning digest at times each person chooses, plus edit, undo, history, CSV and calendar export.

Key decisions

The AI reads, the code decides. Gemini only turns a message into fields. My code checks every result, rejects dates in the past and asks when something is unclear. If Gemini is down, the bot reads what it can itself and asks for the rest step by step, so it never stops working.

Privacy by design. Clutch stores only a deadline's title, module and date, never the message or image. Each person has their own database file, and nothing is stored until they agree to a short privacy notice. As the admin, I can see who uses it but never their deadlines, and /reset deletes everything about a person.

Free to run, for years. It runs on Google Cloud's always-free tier. I chose an IPv6-only server, because a public IPv4 address would have cost money. A daily AI allowance per person keeps everyone inside Gemini's free limits.

How I built and tested it

Every push runs a linter and 95 unit tests on GitHub Actions. I release in tagged versions (v1.0.0, v1.1.0, v2.0.0) with release notes, and deploy with a setup script and a service that restarts the bot if it crashes.

Unit tests weren't enough for a chat app, so I wrote an end-to-end harness. It sends messages and button taps through the bot's real routing, as three users at once. It caught bugs the unit tests missed, such as buttons that did nothing and a new message being mistaken for the answer to an earlier question.

What I learned

  • Treat AI output as untrusted input: validate it, and have a plan for when the AI is unavailable.
  • Free tiers are design constraints. They shaped the network setup, how often the bot checks for messages and the per-person limits.
  • Real users find what tests don't. Letting friends use it led to the privacy notice, per-person data and a feedback command.
